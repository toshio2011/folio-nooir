## XTCH cache recovery and cross-format refresh — 2026-10-20

This section supersedes the earlier note that XTCH thumbnail generation was left unchanged. The user clarified that covers disappeared only in newer 1.6.6 builds and asked to restore the previously working Refresh Book Cache behavior with the smallest safe change. ### History and cause

- Source comparison against the protected 1.6.5 baseline and tags 1.6.2/1.6.3 found the same two-plane XTCH thumbnail path allocating the complete page. A normal 480×800 page needs a contiguous **96,000-byte** buffer in those versions as well as the old 1.6.6 path. No smaller historical streaming implementation was found.
- The supplied COM3 log recorded a largest free block of about **65.5 KB** with about **90 KB** total free when `Failed to allocate page buffer (96000 bytes)` appeared; BLE was disconnected at those failures. This is a contiguous-allocation/fragmentation failure. The log proves the cache generator failed in that session, but no prior cache snapshot proves whether earlier displayed covers were generated by Nooir or preserved from an older cache.
- The 1.6.5 change `a56a7f07` corrected the 2-bit grayscale palette mapping. It changed thumbnail tone, not the allocation strategy. No XTC reader, cover-extraction or container-compatibility path was changed in this repair.

### Targeted repair and format coverage

- XTCH (`bitDepth == 2`) `thumb_HEIGHT.bmp` generation now streams each existing XTH plane through a bounded reducer instead of allocating the 96 KB source page. It retains the same target scaling, palette and dither, and writes to a temporary BMP that is length/header-validated before commit. Existing complete thumbnails remain cache hits; incomplete files are replaced only after a complete temporary image is ready. The 1-bit XTG thumbnail path is unchanged.
- For 480×800 to 132×220, reducer workspace is **26,694 bytes**; the admission gate requires at least **68,166 bytes total free** and a **26,854-byte largest block**, including 40 KB post-workspace reserve, 8 KB fragmentation margin and 512-byte stream chunk. It admits the log's BLE-disconnected 90 KB / 65.5 KB sample. With BLE-connected free heap near 35 KB, it defers safely and leaves the source book and existing cache untouched. Optional 360-pixel HQ generation is deferred when that reserve cannot be maintained. BLE admission, stop/reconnect policy, XTC rendering and refresh cadence are unchanged.
- Shared Refresh Book Cache support remains in place for **EPUB, CBZ and XTC/XTH**. Recent Books and Home retain their format branches. The Library handler previously refreshed XTC metadata but did not regenerate a missing XTC thumbnail; it now calls the same XTG/XTCH thumbnail generator and updates Recent metadata without changing reading progress or synopsis. TXT/Markdown readers do not have generated cover thumbnails.
- `isValidBookThumbnail()` now rejects header-only/truncated BMPs by checking the file data extent. The explicit refresh path no longer deletes an invalid 220-pixel XTCH file before the temporary replacement is ready; the bounded 32-path missing-thumbnail memo is cleared after manual refresh.
